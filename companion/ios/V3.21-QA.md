# v3.21 (22): connection recovery and complete TV episodes

Connection checks now require repeated failures and a 45-second absence of
successful traffic before showing an outage banner. Successful API/image
responses clear stale warnings immediately. Large index transfers use an
independent pool; route changes and retryable reads drain/recreate the small
API pool without cancelling or replaying writes. Saved server/session handling,
normal certificate verification and explicit authentication expiry are retained.
Failed collection watch orders retry after a successful reconnection, retaining
the selected view and last good content. This improves recovery; the cause of
the user's recurring production outage is not established or declared resolved.

TV details use `/api/tv/episodes` to combine verified local files with Sonarr's
complete known episode catalog. Cards show number, title, optional thumbnail,
availability and Play or Interactive Search. Upcoming, missing, downloading,
importing, unknown and Sonarr-only files are separate states. Provider paths
cannot authorize playback outside the app's indexed show files. Local-only
browsing survives provider failures and older servers.

Interactive search is restricted to owner/admin accounts with TV access and the
existing external-integrations entitlement. Results show quality, size, indexer
and rejection reasons. Only an explicitly chosen accepted cached result can be
submitted. Account/show/episode-bound tokens expire after ten minutes. Current
queue/local evidence is rechecked, and concurrent taps or ambiguous failures
do not replay a grab. Integration keys remain on the server. Metadata is cached;
indexers are searched only on user action.

Other accounts retain the existing Seerr season-request workflow, preselecting
the current eligible season. Seerr's current workflow requests whole seasons;
it does not claim to submit an individual-episode request. Sonarr must already
manage the correctly matched series. A TMDB identity may be cross-referenced to
TVDB through the configured Seerr service. No title-only mapping is used.

The new episode API requires the accompanying reviewed server update. Install
through the normal GitHub/image/Unraid flow after review; no deployment is part
of this pass. Source is also included at `companion/ios` in the server PR so
model tests and a simulator compilation can run together in Mac CI.

Windows validation: existing 56 mobile wiring/JavaScript checks pass; one Swift
syntax check is skipped without a compiler. Five new executable Swift tests
cover the warning policy, simulated ten-minute healthy traffic, exact playback
identity, missing cards and provider-outage fallback. These require Mac CI or
`bash scripts/validate-ios.sh`; source checks are not device acceptance.

Device acceptance still required on iPhone/iPad: use for at least 15 minutes on
LAN and tailnet, resume after backgrounding, change networks, interrupt/restart
the server, verify genuine session expiry, retry a timed-out watch order, browse
an empty/partial season, inspect search results without grabbing, explicitly
choose one test release, and refresh until downloaded/imported status is accurate.
Check missing artwork, Specials/multi-episode files, Sonarr outage, ineligible
accounts/plans, queued duplicates and request-service failure. No real indexer
search, download or live server write was performed while preparing this pass.
